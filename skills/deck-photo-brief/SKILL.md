【模板: 攝影 Brief Deck (Photo Brief)】

【意圖】
把「客戶行銷部門的定位與策略」「設計部門的風格提案」「使用者自提的攝影棚條件」三份輸入，轉成一份**攝影師拿了就能開拍**的簡報。
產出物是單檔 HTML deck，16:9 橫向翻頁，版面 960 × 540 pt。
讀者有兩種、看的段落不同：**客戶**先看 Part 1／Part 2 決定方向，**攝影師**現場翻 Part 3 執行。
**排版方案的提案在範圍內，最終行銷圖不在。**
Part 2.5 的 J 版式產的是**示意稿**：標出文字區的範圍與位置，讓排版意圖在拍攝前就定案。
它刻意不追求精確對位——攝影師本來就會拍廣再裁切，標死反而綁住取景。
拍完之後拿真實素材排出可發布的成品行銷圖，是另一條線的事，不歸本 skill。

【輸入】
- **提供方 A（行銷部門）**：產品行銷定位、TA 輪廓、行銷策略、視覺規劃
- **提供方 B（設計部門）**：色彩情緒設定、視覺提案稿、**色 × 場景指定**（例如 RED→廚房、GREEN→咖啡廳）
- **提供方 C（使用者自提）**：攝影棚選項與參考圖片，schema 如下

```yaml
studio_options:
  - name: 攝職島 B 區
    type: 實景棚                      # 白棚素棚 / 實景棚 / LED 虛擬棚
    scene_themes: [臥室, 客廳, 電視櫃]  # 對應鏡位表的 scene_theme
    style: 日系簡約                    # 居家·現代簡約·北歐·韓·工業·vintage·日式…
    size_ping: 30
    natural_light: true
    reference_images: [b-01.jpg, b-02.jpg]   # 直接餵生圖，不只是文字描述
```

**棚型決定鏡位類型**：白棚／素棚 → 商品照；實景棚 → 演示情境。這條連動讓生圖 prompt 的「類型」與「環境風格」兩格不必分開問。
**色 × 場景配對是吃進來的參數，不是本 skill 要推導的東西**。文件裡推不出來也不需要推。

【三段式結構 — 順序不可調換】

三段的順序本身是規格，不是建議。**不許重排、不許合併、不許只出其中一段。**
每段頁數一律由真實資料算出來（persona 幾個就幾頁、鏡位幾顆就幾頁），**不許為了湊頁數灌內容，也不許為了省事砍段**。

### Part 1 — 行銷 Brief（含 1.0 產品規格）

| 節 | 必要內容 | 頁數規則 |
|---|---|---|
| 分隔頁 | 大數字 ＋ 雙語章名 ＋ 本章子目錄清單 | 固定 1 頁 |
| **1.0 產品規格** | 產品名稱／型號、MSRP 建議售價、產品顏色數與色名清單、三大賣點關鍵字＋對應規格值 | 1 頁 |
| 1.1 定位矩陣 | 雙軸象限（品牌發展 × 產品功能），四象限各帶 bullet；競品 logo 依座標放置，自家品牌框出 | 1 頁 |
| 1.2 優勢與挑戰 | SWOT 2×2，四象限固定命名，每格 2–3 條 bullet（帶具體規格數字） | 1 頁 |
| 1.3 受眾輪廓 | 總覽頁：N 張人物卡（標籤名稱＋頭像＋2–3 句生活型態）；人物誌頁：職稱／姓名／頭像／3–4 句敘述 ＋ 背景資訊（性別·年紀區間·居住地·家庭狀況·教育程度）＋ 消費行為（興趣·目標·痛點·使用社群） | 總覽 1 頁 ＋ **每個 persona 一頁** |
| 1.4 市場溝通主軸 | 3 個核心概念，文氏圖排列，各帶 2–3 句說明 | 1 頁 |
| 1.5 產品形象 | 參考品牌清單 ＋ 情境參考圖組 | 1 頁，**此節可選**（欄位密度最低，換案可能整節省略） |
| 1.6 產品切角 | 每案提案：提案編號／主標語／產品命名／副標／CONCEPT 段落／情境參考大圖 | **每提案一頁 ＋ Recap 表格 1 頁** |

**提案數不許寫死 3。** 原檔是 3 個提案、3 個 Mood Board 方案，但那是提案類簡報的慣例、不是規格——一律當成「可變數量的重複區塊」。

### Part 2 — 設計風格提案

| 節 | 必要內容 | 頁數規則 |
|---|---|---|
| 分隔頁 | 同 Part 1 | 固定 1 頁 |
| 2.1 品牌識別段 | 品牌理念框架（四段式因果鏈）／品牌命名故事／識別系統框架（LOGOTYPE → IDENTITY → SYSTEM）／主標語 | 版型與框架句型**固化**，欄位裡的值隨品牌換。⚠️ **待補**：原料註明「品牌識別段的固化範圍尚待確認」 |
| 2.2 Mood Board | 每個方案固定 3 頁：① 視覺方向（方案代號＋名稱／CONCEPT 一句話／KEYWORDS 3 個／搭配切角回連 1.6 的對應提案／主視覺大圖）② 情境氛圍照（攝影風格說明 ＋ **5 張**參考圖）③ 資訊排版風格（排版調性說明 ＋ **3 張**排版參考圖） | **每方案 3 頁 ＋ Recap 1 頁**；三方案骨架完全相同，只換值 |
| 2.3 色彩故事索引 | 一句話總綱 ＋ 每色一張情境人像 | 1 頁 |
| 2.4 色彩情緒頁 | 固定六欄骨架：`色號＋色名 → 故事標題(英｜中) → MOOD 情緒 → PLAYLIST 歌單 → MOMENT 時刻 → 收尾標籤`；配情境大圖 ＋ 右側兩張產品實拍小圖 | **每色一頁** |
| 2.5 排版方案比較 | Hi-Fi 設計稿多版本並排給客戶挑：每個方案一張設計稿 ＋ 稿上標出文字區範圍與位置的虛線框 ＋ 留白比例 ＋ 方案編號與一句話說明 | **用 J 版式**；1 頁放 2–3 個方案，方案數 = 實際設計稿版本數 |

收尾標籤隨品牌敘事變動（本案為「MUSIC × MOOD × MOMENT」），**不是固定文案**。
色彩情緒頁的**骨架固化、值每案輸入**。原檔六色頁彼此就對不齊（側欄標題與大圖烤字六頁對不上四頁、色名標籤寫錯兩處、PLAYLIST 詞彙三頁不同），**不許整批拿原檔的值當範例硬編碼**。

### Part 3 — 攝影表與前置規劃

固定頁序骨架：**封面 → 總覽 → 時間軸 → 棚區 → 標準鏡位清單 → KV →（每色：氣氛參考 → 鏡位網格 ×N）**，可選的獨立主題企劃頁插在該色的氣氛參考之後。

| 段 | 版式 | 頁數規則 |
|---|---|---|
| 封面 | A | 1 |
| 拍攝資訊 OVERVIEW | B | 1 |
| 拍攝時間軸 Timeline | C | 1 |
| 拍攝區域 Shooting Area | D | 1 |
| 每個場景的標準鏡位清單 | E | 1 |
| 主視覺 KV | F | 1 |
| 每色氣氛參考 | G | **每色 1 頁** |
| 每色鏡位網格 | H | **每色 `ceil(該色鏡位數 / 10)` 頁**；張數平均分到各頁，餘數給前面的頁 |
| 獨立主題企劃 | I | **可選**，只有敘事複雜度明顯高於其他場景時才加（本案六色只有一色用到） |

總頁數 = 6 ＋ Σ(每色 1 ＋ ceil(該色鏡位數/10)) ＋ 獨立主題頁數。**不預設 25 頁**——那是本案的數字，不是模板的數字。

【版面骨架 — 540 pt 切四段，所有版式共用】

**先切區塊、每區有職責，再把內容放進去。** 反過來做（先放元素、剩下都算留白）就會得到原檔那種頁面：標題群擠左上、去背窗孤零零在右上、圖在中間，圖以外全是無主的留白。

| 區 | y 範圍 | 高度 | 職責 | 空的時候 |
|---|---|---|---|---|
| **Header** 頁首 | 0 – 108 | 108 | 頁面標題群（前導標籤／大標／**情境資訊行**）＋ **右側輔助元件**（Shot 範圍標籤、產品去背窗、色環、滿版橫幅） | **高度固定不塌**，下一區一律從 108 起算 |
| **Content** 主體 | 108 – 432 | 324 | 該版式的主體：圖列／表格／卡片／清單 | 主體在區內垂直置中 |
| **Meta** 補充資訊帶 | 432 – 493.2 | 61.2 | **N 欄並排的「標籤 ＋ 值」** | **沒有資料就把高度讓給 Content**（延伸到 493.2）。**不留空帶** |
| **Footer** 頁尾 | 493.2 – 540 | 46.8 | 分隔線 ＋ 頁碼 | 固定，**每一頁都有、每一頁同一個 y** |

四個切點全部落在 3.6 pt 底格上（30× / 120× / 137× / 150×）。**切點的實測依據、欄位規格、空槽長相全部在 `DESIGN.md` §5-0 與 §6-8**，這裡不重複。

**哪些版式有 Meta 內容（本模板的預設對應，缺資料就往下讓）**

| 版式 | Meta 欄位 | 來源欄位 |
|---|---|---|
| A 封面 | 品牌行（無標籤單行變體） | `project.brand` / `product_line` |
| **G 氣氛參考** | **MOOD 情緒 ／ PLAYLIST 歌單 ／ MOMENT 時刻 ／ PROPS 道具** | `colors[].mood` / `.playlist` / `.moment`（三格來自 [ST] 色彩情緒頁）；**道具沒有資料就留標好的空槽**，不編值 |

| E 標準鏡位清單 | 適用場景 ／ 清單組成 | `colors[].scene` 推導 ／ `standard_shots` 長度推導 |
| I 獨立主題企劃 | MODEL 模特 ／ 場次 | `themes[].model_spec` ／ `colors[]` 的時段·棚區·場景 |
| B ／ C ／ F ／ H | **無** — Content 直接延伸到 493.2 | — |

**兩條紅線**：① Meta 缺資料一律留空槽寫「待補」，**不許為了填滿而灌內容或編值**；② 主體撐不滿 Content 區的唯一正當理由是**尺寸被寬度鎖死**（G-1 單列大圖就是這種），這種頁把餘裕留在區內置中，不是拉伸圖片。

【版式池 — 10 種，不許新增或改造版式】

**數量由內容決定**，同一版式可在不同章節重複使用；但**版式本身只有這 10 種**，缺內容就不出那一頁，不許為了填版面自創第 11 種。

- **A 封面** — 滿版 `#262626`。**Header**：一排產品色點（直徑 22.1、間距 28.8）在區內垂直置中。**Content**：66 pt 產品名 ＋ 18 pt 固定副標「拍攝計劃 Rundown ｜ Shooting Reference for Photographer」＋ 貼齊 Content 區下緣的橘色直線（x=43.2、高 50.4）帶出日期時間與地點。**Meta**：品牌行。**Footer**：分隔線改用深底弱色 `#9b978e`，y 與其餘 24 頁一致。**整份只有 1 頁。**
- **B 總覽資訊卡** — **Header**：滿版產品橫幅圖，寬 960、高 ＝ Header 區高（108）。⚠️ 原檔是 960×199，那個高度會壓掉半個 Content 區，**不要照抄**。**Content**：左側 4 組「標籤／值」列**撐滿整區**（列距 = 區高 ÷ 列數，每列下方一條 554.4 細線，末線離分隔線留 21.6）＋ 右側 284.4 見方深色卡垂直置中（產品名 24 pt ＋ 系列 ＋ 3 組小欄位）。**Meta**：無，Content 延伸到 493.2。裝**專案層**欄位：日期、時間、地點、負責人、出貨／上市日、色數。

**H 的頁首只有一種結構**：左邊「色名 ｜ 場景」＋ 底下情境資訊行、右邊「Shot NN–NN」＋ 底下張數行，四格的 y 由 Header 區固定（左 30.7 / 52，右 29 / 52）。

**J 的存在理由是把排版意圖前置到拍攝之前。** 原本的流程是攝影師先拍、設計師拿到素材才排版，結果常常「產品太大、任何字壓上去都會壓到產品」，只能回頭重排。J 讓客戶在開拍前就挑定排版方案，挑定後那個方案的文字區範圍**回灌成鏡位的取景要求**（拍廣、留出文字區），不是事後補救。

**J 與 H 不許混淆**：J 是**成品長相**（照片 ＋ 文案 ＋ 標註框），給客戶挑；H 是**要拍的鏡位樣張**（純照片 ＋ 編號），給攝影師照著拍。J 的稿上有文字、H 的圖上一個字都不許有。

【便當盒 grid — 鏡位網格的排法】

G 與 H 兩種版式的圖片區走同一套**求解式**：**列高是算出來的，不是寫死的**。但**列數不一樣**——H 固定兩列、不做三列；**G 預設單列**（四種變體見下方〈G 的排法〉）。

**列高公式（唯一的算法，G／H 共用）**

```
列高 = (可用寬 − 該列所有縫的總寬) ÷ Σ(該列每一格的寬高比)
```

可用寬 = 該列左右邊界之間的距離（滿版時 873.6）；縫是同頁單一常數。
複驗（[SP] 原檔實測）：p16 五格比例和 3.505、可用寬 874.2、縫 4×5.9 → 算 242.7，實測 242.8；p10 四欄比例和 2.749、可用寬 874.9、縫 16.5 → 算 312.3，實測 312.4。

**三條規則，一條都不許破**

1. **每列一個 `display:flex` 容器**，容器 `height` = 該列列高，`gap` 是同一頁的單一常數（同頁所有縫等寬）。
2. **每張圖 `height:100%; width:auto`** —— 高度由列高決定，寬度由圖片比例決定。不許寫死寬度、不許用 `object-fit: cover` 裁掉內容。
3. **`justify-content: flex-start`（靠左對齊），不撐滿。** 右邊留白是正常的：**不許用 `space-between` 把縫撐開**，也不許為了填滿右緣去拉伸圖片。

**圖片比例只用五種**：`4:5`／`3:2`／`2:3`／`16:9`／`1:1`。
原檔量到的 0.75、2.00、2.05 三種一律**就近收斂**：0.75 → 4:5，2.00 與 2.05 → 16:9。**不許新增比例。**

**版型庫**（**H 專用**；G 走下方〈G 的排法〉的四變體。列結構 ＋ 適用張數；實測出處是本案 25 頁的量測值，單位 pt）

| 版型 | 列結構 | 張數 | 實測出處 |
|---|---|---|---|
| `uniform-4x2` | 兩列各 4 張，全頁同比例同尺寸 | 8 | 3:2 = 212.1×141.4／218.8×145.9；16:9 = 210.8×118.6 |
| `uniform-2x2` | 兩列各 2 張，整組水平置中 | 4 | 16:9 = 307.9×173.3，縫 10.0 |
| `mixed-2rows` | 兩列等高不等寬，兩列張數可以不同 | 8–10 | 5+5（列高 197.9）／4+5（列高 183.1）／4+4（列高 201.5） |
| `hero-left-two-rows` | 左側 1 張跨兩列直圖 ＋ 右側上下兩列 | 8 | hero 264.7×330.8（→4:5），右下列 189.8×126.5（3:2） |
| `hero-right-two-rows` | 左側上下兩列 ＋ 右側 1 張跨兩列直圖 | 6 | hero 269.7×421.6（→2:3），左側列高 198.1 |
| `wide-pair` | 上列多張小圖 ＋ 下列 2 張寬圖 | 7 | 上列 5 張列高 198.7；下列 2 張 405.4×198.0（→16:9） |
| `banner-tail` | 兩列等高，末格用寬幅收尾 | 8 | 末格 379.0×189.5（→16:9），列高 189.5 |

**版型怎麼選（H 的機械規則，不許憑感覺）**

1. 該頁有格子標了 `hero: true` → 依 hero 落在哪一側選 `hero-left-two-rows` 或 `hero-right-two-rows`。
2. 沒有 hero 且全頁同比例 → `uniform-4x2`（8 張）或 `uniform-2x2`（4 張）。
3. 其餘 → `mixed-2rows`；張數為奇數時上列多一張。

**主圖一律由資料欄位 `hero` 指定，生成器不許自行挑主圖。** 原檔的主次配置和鏡位編號完全脫鉤（第 01 號、第 13 號、第 16 號都當過主圖；同樣是 Logo 特寫，一頁放大一頁不放大），從鏡位文字推不出來——沒標 `hero` 就走 uniform 版型，不猜。

【G 的排法 — 單列大圖 ＋ 四種變體】

**G 預設是單列大圖，不是兩列小圖。** 這是 G 和 H 最大的體感差別，也是最容易做錯的地方：把 G 排成兩列，圖就縮到 H 的尺寸，需求方一眼就看得出「圖太小」。

**列高的合理範圍**（[SP] 原檔六個 G 頁 ＋ 八個 H 頁實測，單位 pt）

| | 列高實測 | 佔頁高 540 |
|---|---|---|
| **G 單列**（p7 / p10 / p13 / p16） | 272.0 ／ 312.4 ／ 266.1 ／ 242.8 | 45–58% |
| **G 兩列變體**（p19 / p23） | 179.8 ＋ 141.4 ／ 193.6 ＋ 213.5 | 兩列合計 59–75%，另有一張跨列／出血大圖撐場 |
| **H 兩列**（八個 H 頁） | 118.6 – 201.5 | 22–37% |

**單列列高下限 210 pt**——訂在 H 的實測上限 201.5 之上，意思是 **G 的列高不許掉進 H 的區間**。算出來低於 210 就改走 G-2，不是就這樣出。上限是垂直預算（grid 頂到底部分隔線之間），撐不下就夾住，右邊留白，**不許為了填滿去拉伸圖片**。

**圖片區在 Content 區裡置中**，不是切齊區頂。原檔實測就是置中的結果：p16 列高 242.8、實際落在 y 212.3，用「預算 172–489 置中」算出來是 213.2；p13 列高 266.1 落在 218.0，算出來 213.2。切齊頂端會在底下留一條空帶，看起來像漏排了東西。
（區塊化之後垂直預算換成 Content 區 108–432 ＝ 324，比原本的 172–489 ＝ 317 還多 7 pt——去背窗不再從上方擠壓 grid。）

**四種變體與判定條件（機械規則，依序判，第一個成立的就是答案）**

| 變體 | 判定條件 | 結構 | 實測出處 |
|---|---|---|---|
| **G-3 跨列** | 有一張參考圖標了 `span: true` | 上下兩列 ＋ 標記那張在右側跨滿兩列；標記**之前**的圖進上列、**之後**的進下列 | p19（跨列圖 325.5 見方；兩列 179.8 ＋ 141.4） |
| **G-4 出血** | 有一張參考圖標了 `bleed: true` | 標記那張貼右頁緣出血：寬 360，**高度切齊 Content 區**（不是原檔那種 y=0 到 540——那會同時壓掉 Header／Meta／Footer 三個區）＋ 其餘分上下兩列，**張數為奇數時下列多一張** | p23（兩列 193.6 ＋ 213.5） |
| **G-2 兩小疊** | 沒有標記，且單列列高 < 210 | 把**最寬的兩張**折成一個上下疊的直欄，其餘維持單列，重算列高 | p7（272 的位置放兩個 135.4）／p10（312 的位置放兩個 152） |
| **G-1 單列** | 以上都不成立（預設） | 4–5 張等高排成一列 | p13（266.1）／p16（242.8） |

**跨列／出血那張由資料標記指定，生成器不許自行挑**——同 `hero` 的規矩。沒有標記就走 G-1／G-2，不猜。

**折疊欄怎麼進列高公式**：一個上下疊的直欄，欄寬 = (列高 − 縫) × k，其中 **k = 1 ÷ (1/r₁ + 1/r₂)**（兩張 1:1 → k = 0.5；兩張 16:9 → k = 0.889）。它的寬度隨列高變，所以列高公式改寫成

```
列高 = (可用寬 − 縫總寬 + 縫 × Σk) ÷ (Σ單格比例 + Σk)
```

**產品去背窗是獨立元件，不算在參考圖張數裡、也不進 grid。** 六個 G 頁都有。它在原檔裡是那張 **960×199 六色排排站橫幅**被裁切窗切出來的一格（x 座標大幅跑到頁外，只露出一小塊），量圖時**必須先排除**，否則 5–7 張會被誤算成 6–8 張、比例和也會被那個 ar≈4.8 的怪值污染。

**位置與尺寸（區塊化之後改成一組，四個變體共用）**：它是 **Header 區的右側輔助元件**——右緣對齊 916.8、在 Header 區內垂直置中（上偏移 10.8），高度由 Header 區推導（108 − 2×10.8 ＝ **86.4**），寬度由鎖死的 **151.3 : 111.4 比例**推導（≈ **117.3**）。
⚠️ **原本的「固定 151.3×111.4、錨在 (765.1, 49.9)」不能用了**：111.4 高的窗底緣落在 161.3，會戳進 Content 區 53 pt，Header 區就守不住。比例照舊鎖死（不許變形），只有尺寸改成由區塊推導。
連帶**廢掉「位置隨變體走」那三條**（G-1／G-2 右上、G-3 上移、G-4 移左側）——G-4 的出血圖現在只在 Content 區裡水平出血，不再佔滿右半頁，所以去背窗在四個變體裡都待在同一個地方。**少一個特例，不是少一條規則。**

**G 的參考圖是 5–7 張**（[SP] 六頁實測 5／5／5／5／7／6，合計 33 張），不含去背窗。

- 本案六組實拍落在 12–17 顆之間。

- 加的例子：把「吸附」動作延伸到該場景的金屬立面（吸附冰箱門、吸附辦公桌隔板）、夜間氛圍收尾鏡等。加碼屬於「該不該加」的判斷題，**不可複製到別的案子**。

【生圖規格】

模型走 **gpt-image-2**。客戶不會給 prompt，**skill 自己組**。

**prompt 由五要素組成**（一次生成 = 從五格各挑一個值）

| 要素 | 值域 |
|---|---|
| **類型** | 商品照（無人、產品為主）／演示情境（有人物或手） |
| **鏡位** | 全景／中景／產品特寫／局部特寫（Logo・喇叭網・接孔・**掛勾扣具**）。**「俯視」不是並列的第五個值**，它是局部特寫這一類的拍攝角度屬性 |
| **環境風格** | 主題陳設 × 風格 × 光線。**以使用者提供的棚景參考圖為視覺基礎**，主題陳設與風格直接取自棚景 schema，不自由發揮。光線值域必須涵蓋日／夜兩極——本案六組有五組白天自然光、一組夜晚燭光／檯燈，**不許預設白天** |
| **手勢動作** | 無手／單手持／雙手持／**手持情境道具（非產品）**／**吸附平面**（手機・平板・金屬櫃門・辦公桌隔板…）／掛鉤勾包。兩點註記：「手按按鍵」是單手持的特寫變體、不是互斥值；「吸附」不許寫死成「吸手機」，否則遇到新對象直接落在值域外 |
| **設計構圖** | 產品置中／偏側留白／對角線／前景虛化／**背景虛化**（人物在後模糊、產品在前清楚）／框景構圖（⚠️ **待補**：是否獨立成一個值，原料標為待判斷） |

**一致性規則**：同一場景保持同空間、同模特、同光線，**只變鏡位／手勢／構圖**。換場景才換空間與光線。

**⚠️ 排版不是鏡位圖的參數。**
本案 92 張鏡位圖**沒有一張帶文字疊加**，連 Shot 編號都是簡報上疊的標籤、不是燒進照片。把排版塞進鏡位圖 prompt 是空跑，排版屬於 Hi-Fi 設計稿階段的參數。
攝影師本來就拍比較廣再裁切，後製有餘裕——**簡報裡的排版標示功能是溝通意圖，不是精確規格**，標成精確反而綁死取景。
✅ **已解決**：「排版大概範圍與位置」走 **J 版式**（Part 2.5 排版方案比較）。本案 25 頁沒有這一段，那是原檔的缺口、不是模板的缺口。客戶在 J 頁挑定方案後，該方案的文字區範圍回灌成鏡位的**取景要求**（拍廣、留出文字區），**不進鏡位圖的 prompt**——上面那條「排版不是鏡位圖的參數」照舊成立。

**每顆鏡位攜帶的資料**（前半段生成時就填得出來，最後兩格實拍後回灌）

  product_type: 迷你藍牙音箱      # 用來配對同類產品

  props: [木桌, 筆電, 植栽, 咖啡杯]           # 攝影師要的第二件事，不能省

【輸出】
- 單檔 HTML，版面 960 × 540 pt（16:9）；**不用任何外部圖片 URL**，圖片走本地素材或內嵌。
- **頁容器一律寫成 `<section class="slide" data-screen-label="P01 封面">`**，一頁一個，document order 就是播放順序。
  這不是風格偏好，是 OpenDesign 的硬契約：host 的頁碼、逐頁演講者備註、分頁匯出、Tweaks Picker
  全部靠 `document.querySelectorAll('.slide')` 找頁。**自己另取一個 class（`.sheet`、`.page`、`.card`…）不會報錯、
  不會擋住生成、成品看起來也正常——它只會讓整份 deck 被 host 當成一頁。** 這是會安靜失敗的那種錯，務必照寫。
  版式 class 照舊，掛在同一個 section 上即可（`<section class="slide lay-a">`），兩者互不衝突。
- **翻頁 runtime 自己帶，不依賴 host**：鍵盤 ← / → / PageUp / PageDown / Space / Home / End；
  滾輪與觸控板累積位移過門檻走一頁；觸控橫向滑動 50 pt 以上且大於垂直位移；每頁一顆 dot 並標 `aria-current="true"`；hash 同步。
  **目前頁必須標成 `.slide.active`**（`.is-active` 可當相容別名）——host 的頁碼讀的就是這個狀態，
  四種導覽路徑（鍵盤／滾輪／觸控／dot）都要同步它，少同步一條就會出現「畫面翻了但頁碼不動」。
  捲動定位用 `window.scrollTo(0, slide.offsetTop)`，**不要用 `scrollIntoView()`**（它會去捲 parent page）。
- **🚨 這串 class 名是 host 的保留字，絕對不要拿來當狀態 class**：
  `.deck-counter`／`.deck-hint`／`.deck-nav`／`.deck-floating-nav`／`.deck-floating-reset`／`.deck-controls`／
  `.slide-nav`／`.slides-nav`／`.slide-controls`／`.slide-counter`／`.presentation-nav`／`.presentation-controls`，
  以及 `[data-deck-nav]`／`[data-slide-nav]`／`[role="navigation"][aria-label*="slide|deck"]`。
  host 會對它們下 `display:none !important; visibility:hidden !important`，因為它自備導覽 UI、要把 template 自己那套藏起來。
  **把其中任何一個掛到 `<body>` 上，整份 deck 會整個消失**——畫面全白、零錯誤訊息、頁碼還照常顯示 25 頁，
  是最難查的那種安靜失敗（2026-08-25 實際踩過）。狀態 class 一律自帶前綴，例如 `pb-deck-ready`。
  反過來說，**自己的導覽列（dots／頁碼／控制鈕）應該主動掛 `data-deck-nav`**，讓 host 在 project viewer 裡把它藏掉、
  獨立開檔或 gallery 預覽時照常顯示——這是配合契約，不是繞過它。
- **顯示權交給 host，不要自己隱藏非 active 頁**：預設 25 頁全部可見。
  host 的 deck bridge 會接手顯示與縮圖導覽；template 若自己加 `display:none`，會跟它打架而且列印也會壞。
  這份東西的本質是印刷平面稿，翻頁是附加能力，不能反過來把列印弄壞。
- 完整契約以 `design-templates/AGENTS.md` 的「Deck preview navigation contract」為正本；本段與它衝突時以那份為準。
- **不許編造**：所有數字、色值、鏡位條目必須來自輸入。沒有的內容就不出那一頁，不許用 lorem ipsum 或佔位圖填版面。
